# lck 报错、退出码与排查

> 真源是 `lck <命令> --help` 与命令的实际输出。本表随 0.1.0 编写。

## 退出码

| 码 | 含义 | 典型场景 |
| --- | --- | --- |
| `0` | 成功 | 包含「空结果」（如 `(没有笔记)`、`[]`）——空不是失败 |
| `1` | 运行时失败 | 数据损坏、IO 错误、`notebook.json` 解析失败 |
| `2` | 用法错误 | 参数不合法、未知命令/选项、找不到或匹配到多篇笔记/待办、数据目录不存在 |

**先看退出码，再解析输出。** 用 `--json` 时 stdout 才是结构化数据，stderr 永远不是；失败时 stdout 为空。

## 常见错误与处理

### `用法错误：指定的数据目录不存在：<路径>`

`--data-dir`（或 `LCK_DATA_DIR`）指向的目录不存在。lck **不会自动创建**数据目录——这是刻意的，避免打错路径时静默生成一个空工作台，让用户以为数据丢了。

处理：核对路径；确实要新建工作台时先手工建目录。

### `用法错误：找不到笔记：<关键词>`

关键词在标题与正文里都没有命中。注意搜索是**忽略大小写**的子串匹配，不是模糊匹配。

处理：换关键词，或先用 `lck note list --json` / `lck note search <关键词>` 找到 ID。

### `用法错误：匹配到多篇笔记，请用 ID 或更精确的关键词：`

关键词命中多篇。命令会列出候选（最多 10 条，含标题与 ID）。

处理：用完整 ID，或换更精确的关键词。**不要重试同样的模糊关键词**——结果不会变。

### `用法错误：匹配到多个待办，请用更精确的关键词或 --note 指定笔记：`

`task done` 命中多个**未完成**待办。已完成的待办不参与匹配，所以勾选后同一关键词可能就唯一了。

处理：换更精确的关键词，或加 `--note <笔记ID>` 限定范围。

### `用法错误：<命令> 不接受 <选项>；用 \`lck <命令> --help\` 查看可用选项`

每个命令只接受自己声明的选项与标志（外加全局项 `--data-dir`、`--json`）。传了未声明的一律报错，**不会静默忽略**——静默忽略会让调用方以为参数生效了。

常见情形：

| 调用 | 为什么被拒 | 正确写法 |
| --- | --- | --- |
| `note append X --title T` | 追加不改变标题 | `note edit X --title T` |
| `note rm X --title T` | `note rm` 不接受 `--title` | 去掉 `--title` |
| `note rm X --folder F` | 移动用 `note mv` | `note mv X --folder F` |
| `task list --trash` | `--trash` 只属于 `note list` | `note list --trash` |
| `note list --all` | `--all` 只属于 `task list` | `task list --all` |

命令组不带子命令时默认执行 `list`，参数按 `list` 校验：`lck note --trash` 等价于 `lck note list --trash`。

### `用法错误：--title 不能为空；去掉 --title，或给出非空标题`

传了 `--title` 但值全是空白。这是**刻意的用法错误**，不是当作没传——否则调用方会以为标题生效了。

处理：二选一（去掉 `--title`，或给出非空标题）。

### `用法错误：正文自带标题行，与 --title 冲突；去掉 --title，或去掉正文首行标题`

`note new` / `note edit` 同时给了 `--title` 和以 `#` 开头的正文。这是**刻意的用法错误**，不是静默忽略——静默忽略会让调用方以为标题生效了，而落盘的是另一份内容。

处理：二选一。

### `用法错误：正文为空（用 --body 或 stdin 提供）`

`note new` / `note append` / `note edit` 没拿到任何正文。

处理：用 `--body`、`--body-file <path>`、`--body-file -`，或通过管道喂 stdin。注意**位置参数优先于 stdin**，但正文只从上面几种来源取。

### `用法错误：未知子命令 note bogus`

命令组下的子命令拼错。注意 `lck note bogus --help` 也是这个错误（退出码 2），而**不会**回退显示 `note` 组的帮助——命令组下遇到不认识的 token 一律按未知子命令处理。

### `用法错误：folder rm` 之后文件夹里的笔记去哪了

不是错误，但容易误解：`folder rm` 把文件夹内的笔记**移入回收站**（笔记本身不永久删除），文件夹本身消失。用 `lck note list --trash --json` 能看到这些笔记，`lck note restore <ID>` 恢复。

### `错误：...`（退出码 1）

运行时失败。常见原因：

- `<数据目录>/notebook.json` 损坏或不是合法 JSON
- 笔记文件读取失败、磁盘满、权限不足
- 笔记 id 不合法（正则 `^[a-zA-Z0-9_-]{1,80}$`）

处理：**不要删除或覆盖损坏文件**。先向用户报告具体路径与错误原文，由用户决定。lck 不会自动修复或清理。

## 数据目录相关

| 症状 | 检查 |
| --- | --- |
| 看不到预期笔记 | `lck status --json` 看 `dataDir` 是否是预期目录 |
| 数据目录与 App 不一致 | 读 bootstrap：`<APPDATA>/dev.littlecheck/little_check/little-check-data-location.json` |
| bootstrap 损坏或指向不存在的目录 | lck 会明确失败，**不静默回退**到默认目录（避免出现「数据像丢了」的假象） |

bootstrap 的解析逻辑与 App 共用 `lib/data_location.dart`，两处不会漂移。

## 与同步的关系

lck 与 App、局域网同步读写同一份数据，用同一个 `LocalStore` 做原子写。lck 写入后：

- 改动按内容哈希被识别为**本机侧修改**，下次同步自然推送
- **不需要为同步做任何特判**，也不要手工改 `notebook.json`

如果同步后笔记没出现，先查同步侧（配对、网络），不要用 lck 去「修」数据。
