# AI 与本地笔记

## 阅读页

结果持久关联到原帖 URL（无 URL 时用来源与 ID）。原帖或配置变动后，上次结果仍可查看，界面标记需要重新生成；手动重新生成成功后再更新。处理时可暂停，停止当前请求，重新开始会再次请求，不支持中间续传。成功调用的总用时写入结果缓存。旧版能按原标识命中的缓存在读取时迁移关联，无法从缺少帖子关联的旧缓存中猜测对应帖子。

仅提供 AI 翻译与总结。标题下的翻译入口切换原文与译文，带图帖子另有图片文字翻译入口；右下角总结按钮处理当前帖子，结果显示在正文及 README 之后。没有聊天、陪看或联网问答入口，旧对话文件保留。

结果支持复制、暂停、重试和存为本地 Markdown 笔记，分别放入「AI 翻译 / AI 总结」文件夹，附原帖链接、动作和使用模型。带图调用的附件选择也保存，重新进入恢复结果，不自动再次请求模型。

GitHub 仓库帖子支持拉取 README；AI 调用前自动从 GitHub API 获取并缓存，已有缓存优先使用，可手动刷新。失败明确提示并仅处理已获取的原帖，不编造补充资料。README 文本最大 512 KiB，不静默截断；内容更新后旧 AI 结果缓存失效。资料作为待处理内容传入，不作为指令执行。

## 设置与供应商

设置集中管理主模型、可选翻译模型和识图模型、翻译/总结独立提示词、图片翻译提示词、默认思考强度和请求参数。翻译模型未配置时用主模型，附图任务优先识图模型，未配置时用主模型；使用图片必须开启该模型图片能力。模型和提示词不会继承旧聊天人设或历史。

提示词支持 `{source_text}`、`{target_lang}`、`{action}`，变量未知或超限时提示并保留输入。每次请求明确传入本次是翻译还是总结及实际附图数量。

支持 Chat Completions、Responses、Messages。HTTP / HTTPS 均可保存；客户端分别追加 `/chat/completions`、`/responses`、`/messages`。OpenAI 常见地址以 `/v1` 结束，原生 Anthropic 通常需要 `/v1/`；仅提示，不强制补写。保存不做网络测试，失败保留表单输入。

每个供应商支持多个 Key，默认显示、眼睛切换、命名、启用/停用。启用 Key 按调用轮询，失败不自动换 Key 重复请求；用户可重试。凭据使用 flutter_secure_storage，普通 settings.json 仅存 Key ID 和元数据。编辑已有 Key 时先写新的安全存储条目再保存引用，失败保留原凭据；旧值不自动清理。

模型支持 GET `/models` 拉取、搜索多选、手填 ID、别名及独立参数。别名仅显示，请求始终使用真实 ID。模型页可搜索并应用 102 条 ai-toolbox 预设，应用前说明替换范围并可撤销；始终保持已填请求 ID，填入显示名、能力/容量资料及可适配的参数。

预设数据位于 assets/ai/preset_models.json，原样保留上游 AGPL-3.0 许可与来源 NOTICE，应用许可证页可查看。预设属于上游资料，不能证明当前供应商支持全部参数；SDK 专用且未支持转换的字段不会发送，界面提示。上下文/输出上限是参考能力，默认输出长度不直接取最大容量。

## 参数与图片

默认参数先合并，再由当前模型参数覆盖，默认输出长度 8192。Chat 使用 max_tokens 或显式 max_completion_tokens，Responses 转为 max_output_tokens，Messages 使用 max_tokens。禁止覆盖 model/messages/input/system/stream/凭据等内部字段。Responses 默认 store:false。默认思考强度优先采用预设的协议映射；用户显式配置的思考参数优先，不自动擦除其他字段。不支持某个参数时显示错误，供用户在设置调整。

图片优先读取现有磁盘缓存，发送真实 Base64 图片数据；不要求供应商下载原图 URL。单次最多三张，单图原始上限 12 MiB / 4000 万像素，最长边超过 1536 时缩放，动画使用首帧，处理后单图最大 1.5 MiB。处理会提示，失败停止调用，不退回标题冒充识图。请求体最多 8 MiB，来源正文最多 1 MiB；超限明确报错。拒绝、输出长度耗尽、仅有思考、无正文和无效 JSON 分别提示，已有缓存与笔记保留。

Android 关闭系统自动备份，卸载前需手动导出笔记。请求不把 Authorization 转发到重定向地址，不显示供应商可能回显私人内容的错误响应体。模型调用费用以所填供应商账户为准。

## 信息流历史

每个订阅合并新旧缓存，按 ID 或原帖 URL 更新，默认保留最近七天，可设置 14 / 30 / 90 天。保留期以 published_at 判断，刷新成功或读取缓存时清理过期条目；失败保留缓存。只有首次进入/恢复应用、手动刷新、切换订阅来源触发请求。客户端不能补回从未收到的历史，服务端应自行保留需要的时间范围。

## 笔记管理

支持单层文件夹、新建、重命名、移动。全部笔记、未分类、各文件夹与回收站可筛选。笔记更多操作按钮或长按可移动、删除、恢复。删除先移入回收站；彻底删除、清空回收站需要确认，不自动清空。删除文件夹可保留笔记到未分类，或将其中笔记移入回收站。文件夹元数据单独存在 notebook.json，旧 `.md` 文件和内部 ID 保留。

分享/导出的文件名取笔记标题，清理非法字符、Windows 保留名与过长名称。应用内部仍使用稳定 ID，避免同名笔记覆盖。

Android 文件管理器可选择 Little Check 打开 .md/.markdown：先预览，点击导入才保存本地副本，不修改原文件。支持冷启动及运行中的 ACTION_VIEW、content/file URI 和系统授予的读取权限，最大 2 MiB，UTF-8 编码。某些文件管理器仅提供 application/octet-stream 且 URI 不含扩展名时可能不会列出应用；可使用应用内“导入”。

检查过 [receive_sharing_intent](https://github.com/KasemJaffer/receive_sharing_intent) 的实现：其文件复制路径直接使用外部文件名，且复制发生在长度校验之前，因此这里采用 Android ContentResolver + MethodChannel 的小型原生实现，后台线程限量读取，不创建临时副本。

信息流与笔记图片复用 [cached_network_image / flutter_cache_manager](https://github.com/Baseflow/flutter_cached_network_image)，最多 200 个缓存对象，30 天未使用参与自动清理；重新进入优先读取磁盘缓存。服务端 Cache-Control 过期可能触发后台更新，系统也可清理缓存目录；不保证永远离线可用。

动效沿用统一的短时 easeOutCubic 页面切换、滑动标签、展开与按钮反馈，避免复杂模糊和粒子；默认保留动画，系统减少动态效果作为无障碍适配。多端笔记同步不在本轮范围。
